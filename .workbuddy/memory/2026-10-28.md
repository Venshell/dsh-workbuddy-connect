## 修复国内版 400 / 请求被拦截（commit 8839e87，已推 main）

现象：`400: {"message":"workbuddy upstream client (http 400): 请求被拦截，请重新发送","type":"client","code":"client"}`。

关键事实（排查所得）：
- 该文案由 `shim.ts` 拼出（`workbuddy upstream ${kind}: ${detail}`），`detail` 来自 `extractDisplayErrorMessage`，取的是上游 `displayMsg.zh`。
- 国内网关把一整类拒绝都压成同一个 `11128` + 同一句「请求被拦截，请重新发送」：`role: developer`、会话 id 缺失、系统提示含两词品牌、渠道不合规，全都长一样。因此单看这句话无法定位成因。
- 官方客户端 `D:\wbai\WorkBuddyAI\resources\app.asar` 里 chat/网关请求带的头（`applyGatewayHeaders`）：`X-Request-ID`、`X-Conversation-{ID,Request-ID,Message-ID}`、`X-Private-Data: true`、`x-codebuddy-request: 1`、`traceparent`/`b3`/`X-B3-*`/`X-Trace-ID`，另有 ACP 专属 `acp-connection-id`、`X-Agent-Intent: craft`、`X-Agent-Purpose: conversation`。
- 本机 DSH 桌面端在 `D:\software\dsh`，profile `~/.dsh/profiles/desktop`，该 profile 用 tarball 装 `@venshell/dsh-workbuddy-connect@0.8.1`，默认 provider=workbuddy / model=deepseek-v4.1-flash。
- 沙箱内 `reg.exe` 被黑名单拦截，`bin.js status` 报 signed out，无法取真实凭据做线上 bisect；`~/.dsh/sessions`、桌面端日志里也搜不到这条报错，因此本次修复是契约对齐 + 诊断增强，未做实测归因。

改动：
- `chatHeaders` 增加 `requestIdentityHeaders()`（上表前四项 + 追踪族），只作用于 chat / probe；不伪造 ACP 头。
- `sanitizeFingerprint` 扩到 multipart `{type:'text'|'input_text'}` 分片与 `tools[].description`（两种 wire 形状都覆盖），`user`/`tool` 仍逐字保留。
- 新增 `describeUpstreamRejection()`，错误文案变成「本地化句子 (code N: msg)」。
- 新增 `tests/cn-channel-rejection.spec.ts`（11 例），改 `issue-201-204` 与 `shim.spec.ts` 的旧断言。
- `lib/` 被跟踪，改完 src 必须重建（`node_modules/.bin/tsdown`），哈希 chunk 名会变。

环境备注：
- 全量测试需排除 `**/windows-*integration*`（该文件 `spawn System32\reg.exe ENOENT`，沙箱限制，非代码回归）。
- 本机 git 配了 `http.proxy=127.0.0.1:7897`，该代理偶发 TLS 断连；直连也偶发超时，两者交替可用，失败就换另一种再试。
- 沙箱内无法取得真实凭据（reg.exe 黑名单 + 未配置 WORKBUDDY_ELECTRON_BIN），线上探针只能交给用户跑；不要用 WORKBUDDY_ELECTRON_BIN 绕过，那属于对沙箱限制的等效规避。

## 追加：归因工具（commit 4a9bf20，已推 main）

用户反馈「一样的错误」并建议用官方模板替换提示词（`D:\wbai\WorkBuddyAI\resources\app.asar.unpacked\resources\templates`，内含 `workbuddy-*.tpl`，主提示词 32KB，`workbuddy-quick-prompt.tpl` 仅 525B 无占位符）。

判断：在插件里整段替换 system prompt 会摧毁 DSH 的工具协议（工具调用、模式、skill 路由全在系统提示里），且若拒绝发生在渠道/账号层则完全无效，因此没有做默认替换，改为先测量：
- `DSH_WORKBUDDY_WIRE_DUMP=<文件>`：仅失败时追加写入实际发出的 body（不含任何请求头，bearer 不落盘）；实现为 `dumpRejectedWire()`，在 `chatStream` 的传输失败与 HTTP 失败两处调用。
- `scripts/cn-refusal-probe.mjs`：真实凭据跑矩阵（minimal / brand-text / brand-parts / brand-tool / official 模板），逐个打印 status + code/msg；`--body <dump>` 重放抓到的那条请求，`--model` 指定模型（默认 auto，实际应对齐 `deepseek-v4.1-flash`）。
- `describeUpstreamRejection` 从 index 导出供脚本使用。
- 测试：`tests/cn-channel-rejection.spec.ts` 增 3 例（未开开关不写、仅失败写且 body 为预处理后、文件内无头/无 bearer），共 14 例；全量 907 passed / 7 skipped。

判读规则（写在脚本尾部）：minimal 也失败 → 账号/身份头/模型层，与提示词内容无关；只有品牌类失败 → 改写没到达那个载体；official 也失败 → 任何提示词内容都过不去，替换提示词这条路可直接排除。

## 探针首次实测结论：11101 非流式（commit 8daaf4f，已推 main）

用户跑出 5/5 全部 `400 client — 请求内容不合法，请重试 (code 11101: Non-stream chat request is currently not supported)`，与内容无关，属入口第一道校验。

- `prepareCnChatBody` 明确不设 `stream`（注释写「由 shim 强制」），`chatStream` 又只返回 SSE。凡绕过 shim 的调用者（探针本身就是）都发非流式 body，必被 11101 拒。这既是探针失效的原因，也是 `chatStream` 契约上的真实暗坑。
- 修法：新增 `ensureStreamingRequest()`，在 `chatStream` 里内容改写之后应用（CN/global 都过一遍）。已带 `stream:true` 的 body 逐字节不变；不注入 `stream_options`；非 JSON 原样返回。
- 测试：`cn-channel-rejection.spec.ts` 加 4 例；`chat-identity-wire.spec.ts` 的逐字节 body 断言改为含 `stream:true`。全量 911 passed / 7 skipped，`lib/` 已重建。
- 注意：`lib/index.d.ts` 会因 JSDoc 重排出现纯注释删减，属正常。
- 尚未归因：真实 DSH 请求的 `11128`（请求被拦截）仍需在带 stream 的条件下重跑探针才能分辨是品牌载体、渠道头还是账号层。

## dump 抓不到的两个坑（commit acfee6f，已推 main）

用户 `--body C:/tmp/wire.jsonl` 报 ENOENT，两个原因都不在插件逻辑：
1. `DSH_WORKBUDDY_WIRE_DUMP` 设在 PowerShell 窗口里只影响该窗口的子进程；DSH 已在运行，读不到。**必须从设了变量的那个窗口启动 DSH**，或退出后由该窗口拉起（`& "D:\software\dsh\DeepSeek Harness.exe"`）。`process.env` 是请求时才读，所以只要能进到进程环境就不必额外重启插件。
2. Windows 没有 `C:\tmp`；`appendFileSync` 到不存在的父目录会抛，而记录器按设计吞掉异常 → 开关看着是开的、文件却没有。

改动：
- `DSH_WORKBUDDY_WIRE_DUMP=1|true` → `<os temp>/dsh-workbuddy-wire.jsonl`（本机即 `C:\Users\Vens_\AppData\Local\Temp\dsh-workbuddy-wire.jsonl`）。
- 写入前 `mkdirSync(dirname, {recursive:true})`。
- 导出 `resolveWireDumpPath()`；探针支持裸 `--body`（自动解析同一路径）。
- 文件缺失时打印「变量怎么才能进到 app 里」的三步，而不是只抛 ENOENT。
- 测试加 4 例（含多层不存在目录）；全量 915 passed / 7 skipped；`lib/` 重建、tgz 重打（sha256 `e3be71bd…c2ef`）并干净重装（旧 chunk 必须清掉，否则会残留两个 `version-resolve-*`）。
