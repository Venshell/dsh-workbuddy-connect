# 2026-10-28

## 修复国内版 400 / 请求被拦截（commit 8839e87，已推 main）

现象：`400: {"message":"workbuddy upstream client (http 400): 请求被拦截，请重新发送","type":"client","code":"client"}`。

关键事实（排查所得）：
- 该文案由 `shim.ts` 拼出（`workbuddy upstream ${kind}: ${detail}`），`detail` 来自 `extractDisplayErrorMessage`，取的是上游 `displayMsg.zh`。
- 国内网关把一整类拒绝都压成同一个 `11128` + 同一句「请求被拦截，请重新发送」：`role: developer`、会话 id 缺失、系统提示含两词品牌、渠道不合规，全都长一样。因此单看这句话无法定位成因。
- 官方客户端 `D:\wbai\WorkBuddyAI\resources\app.asar` 里 chat/网关请求带的头（`applyGatewayHeaders`）：`X-Request-ID`、`X-Conversation-{ID,Request-ID,Message-ID}`、`X-Private-Data: true`、`x-codebuddy-request: 1`、`traceparent`/`b3`/`X-B3-*`/`X-Trace-ID`，另有 ACP 专属 `acp-connection-id`、`X-Agent-Intent: craft`、`X-Agent-Purpose: conversation`。
- 本机 DSH 桌面端在 `D:\software\dsh`，profile `~/.dsh/profiles/desktop`，该 profile 用 tarball 装 `@venshell/dsh-workbuddy-connect@0.8.1`，默认 provider=workbuddy / model=deepseek-v4.1-flash。
- 沙箱内 `reg.exe` 被黑名单拦截，`bin.js status` 报 signed out，无法取真实凭据做线上 bisect；`~/.dsh/sessions`、桌面端日志里也搜不到这条报错，因此本次修复是契约对齐 + 诊断增强，未做实测归因。

改动：
- `chatHeaders` 增加 `requestIdentityHeaders()`（上表前四项 + 追踪族），只作用于 chat / probe；不伪造 ACP 头。
- `sanitizeFingerprint` 扩到 multipart `{type:'text'|'input_text'}` 分片与 `tools[].description`（两种 wire 形状都覆盖），`user`/`tool` 仍逐字保留。
- 新增 `describeUpstreamRejection()`，错误文案变成「本地化句子 (code N: msg)」。
- 新增 `tests/cn-channel-rejection.spec.ts`（11 例），改 `issue-201-204` 与 `shim.spec.ts` 的旧断言。
- `lib/` 被跟踪，改完 src 必须重建（`node_modules/.bin/tsdown`），哈希 chunk 名会变。

环境备注：
- 全量测试需排除 `**/windows-*integration*`（该文件 `spawn System32\reg.exe ENOENT`，沙箱限制，非代码回归）。
- 本机 git 配了 `http.proxy=127.0.0.1:7897`，该代理偶发 TLS 断连；curl 直连 GitHub 正常，可用 `git -c http.proxy= -c https.proxy= push` 绕过。
